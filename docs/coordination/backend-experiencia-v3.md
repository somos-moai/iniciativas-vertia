- `backend/transport.py`: middleware ASGI exterior limita escrituras a 64 KiB, cede el event loop entre fragmentos y conserva bytes, `Content-Length` y finalización de streams. No impone un event loop de Windows al despliegue Linux.

El contrato base sigue compatible. `state.users` contiene perfiles de la aplicación; `viewer.capabilities` y `users[].capabilities` permiten comunicar permisos, que se comprueban en backend.

- `credits`: mantiene `used/limit/remaining`; agrega `wallet`, `organization`, `portfolios`, `history`, `runs`, `run_limit`, `rate_limits`. `credit_history` es alias del historial. El ledger público no expone la clave interna de deduplicación.
- `dashboard`: `current/previous/yoy_previous/ytd/previous_ytd`, `comparisons`, `monthly`, `funnel`, `by_owner/by_country/by_sector`, `campaign_performance`, `clm`, `coverage`. Los contadores ofrecen IDs en `drilldown` o `ids`.
- `inbox`: array de hilos `{id,contact_id,subject,last_at,classification,messages:[]}`. `messages` plano se conserva. `email_queue`, `sequences`, `write_today`, `mail_policy`, `email_drafts`, `mail_sync`, `search_runs`, `last_search`, `ai_settings`, `ai_settings_current`, `clm_settings`.
- Acciones: `preview_reveal {prospect_ids,run_id?}`, `reveal_contacts {prospect_ids,run_id?}`, `draft_email` y `send_email` con contacto por `entity_id` o `contact_id`; `save_sequence {contact_id,name?,steps:[{delay_days,subject,body}]}`; `simulate_sequence` por ID; `poll_inbox`/`sync_inbox`; `save_ai_settings`; `configure_credits` exclusivo superadmin; `save_clm_settings` para Innovación/Regional.

- Los campos `amount_usd` y `fx_source` son equivalencias ilustrativas; se conservan `amount` y `currency` originales. No se suman monedas locales como si fueran una misma unidad.

## Validación ejecutada

Entorno PostgreSQL local aislado, loopback puerto 55489, base `vertia_v3_staging`. Las suites crean y eliminan únicamente esquemas aleatorios `vertia_test_*` dentro de esta base. No se ejecutaron suites contra producción.

1. Compilación `python -m compileall -q backend`: correcta.
2. Primera corrida de regresión: 13/15; las dos diferencias eran aserciones de volumen antiguo (`25` contratos y `8` contactos UY). Se actualizaron por requisitos de volumen y se conservaron los controles de país/propietario.
3. Suite ampliada: **27/27 pasaron en 43,22 s**, incluyendo uploads/documentos reales, perfiles, tablero, preview/deduplicación, créditos, 429, correo/secuencias/cancelación, bandeja, configuración aplicada y migración aditiva preservando metadatos privados. La prueba nueva de cancelación detectó que el antiguo `exclude_contact` cancelaba el seguimiento pero no el mensaje en cola; se conectó a `cancel_pending` y se verificó la corrección.
4. Corrida final: **30/30 pasaron en 184,75 s**, incluyendo aislamiento de deduplicación entre carteras y los topes de minuto/hora/día, junto con serialización JSON directa y reutilización de consultas. El host presentó mayor latencia durante la ejecución paralela de las suites de navegador; una inspección de `pg_stat_activity` del PostgreSQL local no mostró consultas prolongadas ni bloqueos de base.
5. Perfilado local directo inicial de `main.state` regional: 1,25 s, de los que 0,56 s eran consultas y 0,52 s agregados. Se redujeron cuatro consultas repetidas de créditos. El coordinador verifica transporte HTTP y navegador con el servidor reiniciado; el backend no ha reiniciado producción.
6. Pruebas adicionales de transporte: **3/3 pasaron en 0,96 s**, conservando exactamente bytes y framing de JSON grande, gzip y streams existentes. Prueba TCP real en puerto local 8001: Node completó 12/12 lecturas consecutivas de `body.json` (4 sin compresión y 8 gzip, entre 0,75 y 4,69 s). Las pruebas posteriores intercaladas con POST mostraron intermitencia en Python 3.14 bajo Windows incluso reemplazando experimentalmente `BaseHTTPMiddleware` por ASGI puro; ese reemplazo no se conservó. El puerto de diagnóstico 8001 se detuvo al terminar. El coordinador cambió únicamente staging a Python 3.12 y verifica la suite de navegador; no se atribuye una solución definitiva a los primeros resultados aislados.
7. Hallazgo de runtime: Uvicorn 0.44 en Windows selecciona `ProactorEventLoop` explícitamente; cambiar `WindowsSelectorEventLoopPolicy` no fuerza Selector. El runner local debe indicar una fábrica real (`loop="asyncio:SelectorEventLoop"`) cuando la versión lo admite. La selección permanece en el runner de staging, fuera del código de aplicación.

## Límites y pendientes externos

- Lusha, Microsoft 365, Claude, POST y firma siguen simulados. La cola es persistente y se procesa por acción/poll del simulador; no se instala un daemon ni se habilita envío externo.
- Las métricas históricas son de demostración. Las equivalencias de moneda están declaradas ilustrativas y no se presentan como cotizaciones.
- La revisión de interfaz, capturas, contraste y publicación corresponde al coordinador y frontend. La publicación requiere aprobación del usuario. Antes de una futura migración en VPS se deben respaldar la base y `UPLOAD_DIR`; en esta tarea no se ha ejecutado ninguna migración remota.
